# Robot Mesh Collision Queries

This package is linked to the app's IK preview. `RigCollisionWorld` prepares imported meshes, filters pairs by group ownership and moving branches, infers localized joint contact regions and validates ordered motion samples. Background tasks keep geometry queries off the UI thread. Drag targets coalesce to display frames (up to 60 Hz). One worker runs at a time; incoming drag targets replace the pending target without cancelling useful work. Each target is solved once and checked as a batch of ordered samples; only the furthest accepted sample is displayed. Each pose still uses its own GPU dispatch. Cancellation and edits invalidate outstanding results. There are no manual contact overrides.

The Swift package pins Euclid to a tested revision for mesh preparation and optional offline volume analysis. Bounds are only an early rejection test. Interactive IK uses `measureOverlap: false`: Metal compute kernels perform triangle crossings and BVH-pruned ray containment in closed solids, with no Boolean construction or starting-pose volume baseline. Every proposed sample is checked. Coplanar surface contact is not penetration. Open meshes have no defined interior and cannot provide full volumetric coverage.

Collision-only proxies use the vendored meshoptimizer v0.25 standard simplifier (`Sources/CMeshSimplifier`, MIT license). Rig proxies target 256 triangles with a 0.001 relative error limit and locked open boundaries; topology/error constraints can leave more triangles. Original vertex positions are reused. Empty results, invalid polygons, lost watertightness or reversed positive volume fall back to the original mesh. No convex hulls or hole filling are used. The reported error is meshoptimizer's approximation metric, not a certified maximum clearance error or conservative collision envelope. Rendering and picking continue to use the original mesh.

Proxies and packed, stackless triangle BVHs are prepared in the background when IK is enabled and retained in Metal buffers across target updates. CPU sweep-and-prune bounds identify candidate part pairs. All candidates for a pose are dispatched together, with one GPU thread per source triangle in each direction. Only transforms, localized contact spheres and query metadata are uploaded; the CPU reads per-pair result flags. Metal handles BVH traversal, surface intersections and closed-solid containment. Edge-ambiguous containment rays are retried in different directions and hold motion if unresolved. Shader compilation is cached process-wide. GPU setup or execution failures hold motion; there is no CPU fallback on the interactive path. Mesh preparation remains CPU work.

Run from the workspace root:

```sh
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer swift test --package-path RoboCar/CollisionQueries -c release
```

The regression fixture rotates a triangulated link through 180 degrees inside a hollow bracket. Their bounding boxes overlap throughout, but the meshes do not. A second pose puts the link into the bracket wall and must report overlap. Other checks cover containment, small solids, touching faces, open meshes, inverted winding, cancellation and invalid budgets.

## Limits

- Imported vertices are normalized and welded on a 1e-6 normalized grid. Negative total volume is reversed, but consistent winding and absence of mesh self-intersection are not certified. No holes are filled.
- Empty/degenerate parts and parts above 20,000 triangles are skipped and reported. The preview may move with partial coverage, not silently claim clearance. Surface-only checks are also reported.
- No pair of different groups is excluded merely because it is adjacent in the hierarchy. Direct parent/child pairs receive a contact sphere only when their rest bounds overlap near the shared hinge axis (within 10% of the smaller part's bounds diagonal). The contact center is the rest-overlap center projected onto the hinge line, so choosing a pivot on the outer end of a shaft does not reject contact farther along that same shaft. The radius encloses the rest-overlap box, with a small numerical margin and a 10% minimum. Callers without an axis direction retain pivot-centered behavior. The region is fixed from rest geometry, never enlarged by proposed motion, and follows the parent pose. Only intersection/containment points within that sphere are ignored. Adjacent-link impacts elsewhere, nonadjacent links, siblings, other branches and ungrouped geometry remain checked. Same-group parts are rigidly attached and are not self-tested. Ungrouped geometry receives no interactive contact allowance. Bounds-derived spheres can overestimate contact on concave parts; this is an inferred tolerance, not an exact CAD joint boundary.
- Interactive IK checks candidate samples, not the starting pose. Existing overlap outside a contact region stops the next intersecting sample even if overlap is decreasing. A clear candidate can escape a starting overlap. Optional volume-analysis mode supports non-deepening overlap but is not used while dragging.
- Interactive checks share a monotonic 250 ms budget across the submitted poses, CPU candidate preparation and GPU wait. CPU preparation is checked at phase boundaries, not preempted. A timed-out GPU submission may finish in the background, but no new submission on that world is accepted until it completes. Its private result buffer cannot affect subsequent results. Timeouts hold the last accepted sample. The app interpolates from the displayed pose to the solved pose using ceil(summed joint travel / 5 degrees) samples, clamped to 1...8, and displays only the furthest accepted sample. Large jumps therefore have wider spacing. This bounded subsampling improves tracking but can miss thin collisions between samples; it is not continuous collision detection or final-pose-only checking.
- Release tests execute actual Metal kernels and compare results against the CPU reference for rotated brackets, crossings, containment, touching faces and joint-local exclusions. A 60-query warmed bracket fixture measured 0.26 ms mean / 0.31 ms p95 on the development Mac. Native `--rig-model path --rig-document path` reproduced a Mount_002/servo block in the saved rig and passed after carrying the hinge direction into contact preparation. Its 60 small out-and-back Debug simulator queries averaged 4.55 ms (p95 4.94 ms, maximum 5.18 ms); preparation took 13.8 seconds. Coverage remained 193/1,024 components, including 43 surface-only parts. These are collision-query timings, not end-to-end frame rates or validation of arbitrary target paths. Physical-device performance remains unverified.
- The original IK solver proposes motion, then this package validates it. Clearance-gradient optimization and global routing are not implemented. A target may be blocked even when an alternate configuration or route exists.
- The repository MangoBot GLB prepared 625/630 components in the simulator, including 538 surface-only parts. This measures preparation coverage, not full-rig collision correctness or physical-device performance.
- Ungrouped model parts remain stationary under the existing rig semantics. This module does not infer ownership or attach disconnected components to moving links.

This module is not a physical robot safety system.
